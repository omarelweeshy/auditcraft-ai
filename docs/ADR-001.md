# ADR 001: Local single-user monorepo

Accepted: 2026-10-09. Next.js web, TypeScript Playwright worker, PostgreSQL and Redis/BullMQ in Docker Compose. Shared core and database packages; UI components stay in the web app until there is a second consumer. SQL migrations keep the database contract explicit. JSONB holds versioned immutable evidence and report snapshots, with relational foreign keys and transactions for ownership and approval boundaries.

The web app authenticates a single administrator using a signed, expiring, HttpOnly cookie. State-changing API requests require a session-derived CSRF token and an exact configured Origin. Worker health uses a separate token. No public report links.

An SQL outbox (queued audit rows) repairs the database-to-Redis enqueue gap. Workers use BullMQ leases and bounded attempts; a reconciler repairs missing jobs. Database transactions serialize findings and report finalization.

Fixture capture fulfills only exact https://fixture.auditcraft.test paths from controlled strings and aborts every other browser request, including websockets. There is no localhost bypass, even in development or production. This enables a production-built local demo without weakening SSRF policy.

Real-site crawling is intentionally disabled in this release. A DNS validator alone is insufficient to prevent DNS rebinding in Chromium. Enabling live auditing requires a pinned-IP egress proxy, response limits, per-request validation, robots enforcement and redirect tests against the actual browser transport.

The deterministic provider uses check-specific templates only. Arbitrary model prose cannot be reliably verified with a regex, so external providers are not enabled. Provider output must meet a strict schema, use known IDs and match approved explanation templates before becoming a pending finding. Human review is always required.
